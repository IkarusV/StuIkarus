Supported Input Formats (click to expand)
  • Legacy character marker:$角色名字-sfw-upperbody$, $角色名字-nsfw-upperbody-sfw-lowerbody$
  • JSON character marker:${"name":"角色名字","angle":"from front","upperBody":"sfw","lowerBody":"hidden"}$
  • Multiple characters (multiple $...$ segments in one tag string):$小红-sfw-upperbody$, standing, $小蓝-sfw-upperbody$, smiling
  • For debugging, match name only: 角色名字, 角色名字[当前] (the actual replacement process does not recognize bare names)
The test performs name matching only: it extracts character names from the input and checks them against the enabled list. It does not execute the full replacement process.
Formal parsing requires $...$ to contain either a name plus a legacy-format suffix or a JSON object. Bare names such as $角色名字$ remain unchanged during actual replacement.
When the input contains multiple $...$ segments, each is automatically identified as a character and its result is displayed in a table.
{{角色启用列表}} Trigger Rules and Differences from Character Triggers (click to expand)
  • Trigger source: Scans only characters registered in the current Character Enablement preset. It does not use the common list or global-preset fallback.
  • Matching method: Performs substring matching against each enabled character's Chinese or English name.
  • Name splitting: Names can use | to separate aliases; a match on any alias triggers the character.
  • Case and spaces: Both are ignored. Trigger text and names are stripped of whitespace and compared in lowercase.
  • Result count: Multiple characters can match at once. Every matching character is included in the {{角色启用列表}} text.
Differences from character triggers ($...$ replacement):
  • Whether the list must be enabled: List triggers must be in the enabled list. For character triggers, the enabled list only determines priority; fallback matches all presets.
  • Matching algorithm: List triggers only perform substring matching. Character triggers use normalizeName plus similarity scoring.
  • Match count: List triggers can match multiple characters. Character triggers select only one best match for each $...$ segment.
  • Input form: List triggers accept any natural text. Character triggers require $...$ to contain a legacy-format suffix or JSON object.
